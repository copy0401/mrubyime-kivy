# AGENTS.md

Android 嘸蝦米 IME 專案 `mruby-ime` ("小蝦米輸入法", pkg `com.example.mrubyime`). Input logic lives in embedded mruby behind JNI. The keyboard is a standard `TextView`/`LinearLayout` view hierarchy (no Canvas), built at runtime from a **Ruby keyboard DSL → IR JSON → Kotlin renderer**, not from the hand-written XML layout. Read `mruby-ime/README.md` (UX spec) and `mruby-ime/SKILL.md` (mruby/JNI/UTF-8 rules) before touching engine, bridge, or keyboard code, and update them when behavior changes.

## Layout

- `mruby-ime/` — the Gradle project; all real work happens here.
- `mruby-ime/app/src/main/mruby/mrubyime_engine.rb` — mruby core: `.cin` parsing, lookup, buffer state. **Build-time source only** (compiled into `engine_irep.c`; ships as bytecode, not as an asset). User Ruby engines are **removed** — the engine always runs the compiled bytecode.
- `mruby-ime/app/src/main/assets/keyboard_dsl.rb` — runtime keyboard DSL: `Keyboard.layout`, context parsing, Builder/ThemeBuilder/PageBuilder/BarBuilder/GroupBuilder/RowsBuilder/RowBuilder, JSON writer, validation. **Compiled to bytecode.**
- `mruby-ime/app/src/main/assets/keyboard_layout.rb` — built-in Chinese + English pages expressed in the DSL. **Compiled to bytecode.**
- `mruby-ime/app/src/main/assets/keyboard_layout.json` — IR generated at build time from the same DSL (fallback if the runtime DSL fails; golden snapshot).
- `mruby-ime/app/src/main/cpp/` — `mrubyime_jni.c` (bridge), `engine_irep.c` / `keyboard_dsl_irep.c` / `keyboard_layout_irep.c` (generated bytecode), `CMakeLists.txt` (links `mruby-ime/mruby/build/android-arm64-v8a/lib/libmruby.a`).
- `mruby-ime/app/src/main/java/com/example/mrubyime/` — IME service (`MrubyimeIME`), `KeyboardView` (renderer host), `KeyboardRenderer` (IR → per-page view trees), `KeyRowLayout` (span/weight/align geometry), `KeyFrameLayout` (cell-sized touch bounds + visual gap insets), `RowsLayout` (row bands that tile the body with half-gaps), `KeyboardLayout.kt` (IR data classes + `KeyboardLayoutParser`), `KeyboardLayoutRepository` (`ThemeResolver` + engine/asset/emergency fallback), `KeyboardLayoutFiles` (user `layouts/keyboard.rb` storage + Android/data mirror), `StepScrollView`, delegation interfaces (`MrubyimeEngineDelegate`, `MrbuMrubyimeEngineDelegate`, `MrubyimeJNI`), and settings (`MrubyimeSettingsActivity`).
- `mruby-ime/app/src/main/res/layout/view_keyboard.xml` — **no longer inflated**; kept only so the `R.id.*` constants used by `KeyboardRenderer` still exist. It is not the live keyboard.
- `mruby-ime/docs/LAYOUT_DSL.md` + `docs/layout_template.rb` — self-contained hand-off package for external layout/theme designers (and AI): DSL reference, colour rules, validation command, prompt template, and a minimal validated layout. Not compiled and not shipped in the APK.
- `mruby-ime/app/src/main/assets/mrubyime.cin` — the shipping built-in table: **uniliu 萬國蝦米_unifont_t** (2.0 MB: 30,478 codes / 47,788 `%chardef` entries + a 139,637-line `%phrase` list of `詞 權重` lines (the single-char lines were removed from the table) → `entries` 187,422). It is the **only** built-in table (`assets/dicts/boshiamy.cin` was deleted). The `%phrase` block is the upstream shape — one entry per line with its corpus frequency (`一 213167`, `你好 121`) — so it is readable and editable, at the cost of a slower cold parse (see the load numbers below).
- Root `make_project.sh` — **regenerates the whole project with `rm -rf mruby-ime/` first, and its output predates the current sources (10/27 vs 10/28)**. Never run it to make a change.
- Root `mrubyime-ime.zip` — old source snapshot (backup only); not used by the build.
- `mruby-ime/mruby/` (93 MB) + `3.3.0.tar.gz` are downloaded by `build_mruby.sh`; safe to delete (rebuild re-downloads, needs network).

## Build & verify (no tests, no lint, no CI)

- Full pipeline — mruby ireps + JSON → APK → **installs onto the attached phone**:
  ```bash
  cd mruby-ime && ./build_all.sh
  ```
  It supplies the toolchain that is missing from the environment: `ANDROID_NDK_HOME=/home/cc/Android/Sdk/ndk/30.0.16248370`, `JAVA_HOME=/opt/android-studio/jbr`, and `~/.local/share/gem/ruby/3.4.0/bin` (where `rake` lives).
- APK only, no device side effects:
  ```bash
  cd mruby-ime && JAVA_HOME=/opt/android-studio/jbr ./gradlew assembleDebug
  ```
  Plain `./gradlew` fails (`java` is not on PATH). Verified working; APK at `app/build/outputs/apk/debug/app-debug.apk`.
- Release APK (signed with the debug key, so it installs **over** the debug build and keeps the user's edited `dicts/`/`layouts/`/`engine/` files):
  ```bash
  cd mruby-ime && JAVA_HOME=/opt/android-studio/jbr ./gradlew assembleRelease
  ```
  → `app/build/outputs/apk/release/app-release.apk` (**~1.2 MB**; was ~4.7 MB before the size pass). The signing config in `app/build.gradle.kts` points at `~/.android/debug.keystore` and is only applied when that file exists; `lint { checkReleaseBuilds = false }` is required — release-only `lintVitalAnalyzeRelease` fails on this toolchain. Swap the keystore before ever publishing.

- **Size-optimized release** (all measured): R8 `isMinifyEnabled` + `isShrinkResources` (dex 2,060 K → **77 K**; appcompat was unused and removed, so there is **no androidx dependency** — `LayoutFileProvider` replaces `androidx.core.content.FileProvider`); `useLegacyPackaging=true` compresses the .so into the APK (installed size grows a bit, download shrinks ~3×); launcher mipmaps are WebP; unused res deleted. libmruby is built **minimal** (see `build_mruby.sh`): only the gems the engine/DSL use + `mruby-compiler` (for user layout imports), with `-Os -g0 -flto=thin -ffunction-sections -fdata-sections -fvisibility=hidden -fno-unwind-tables` and `-Wl,--gc-sections -Wl,--exclude-libs,ALL` (CMakeLists mirrors this). .so: 938 K → **~600 K** raw / ~220 K compressed. User Ruby code cannot use `Set`/`Fiber`/`Enumerator`/`Time`/`Struct`/`Data`/`Pack`/`Random` — they are not compiled in.
- Verification is manual: install, enable the IME, type in the settings screen's test field. Only `arm64-v8a` is built — x86_64 emulators cannot load the JNI lib.
- On-device `Log.d` from this app is often filtered; use `Log.i`/`Log.e` for startup diagnostics (`MrubyimeIME: layout JSON bytes=… parsed=true pages=[chinese, english]` is logged once per IME creation).

## #1 trap: editing any `.rb` does nothing by itself

Runtime executes the generated `*_irep.c` arrays. After editing `mrubyime_engine.rb`, `keyboard_dsl.rb` or `keyboard_layout.rb`:

```bash
cd mruby-ime && ./build_mruby.sh    # host mrbc + arm64 libmruby.a + 3 ireps + keyboard_layout.json
```

Cheap syntax check without NDK/network: `mruby/build/host/bin/mrbc -Bengine_irep -o /tmp/x.c app/src/main/mruby/mrubyime_engine.rb` (same pattern with `-Bkeyboard_dsl_irep` / `-Bkeyboard_layout_irep`). The mruby build config is written by `build_mruby.sh` into `mruby/build_config.rb` (**minimal gem list** — enum/array/hash/string/symbol/range/numeric/kernel/proc/object-ext + `mruby-sprintf` + `mruby-compiler`, `-DMRB_UTF8_STRING`, `-DMRB_ARY_LENGTH_MAX=0`, `-DMRB_GC_ARENA_SIZE=4096`, `-Os`+LTO, arm64 only); the root `build_config.rb` is unused. After changing the gem list, `rm -rf mruby/build/android-arm64-v8a` first — stale gem objects are not pruned.

## Engine / data-path facts

- Startup: `MrubyimeIME.onCreate` only resolves the **id + signature** (`DictionaryRepository.activeId` / `signature`) — no table bytes — and then either reuses the engine a previous instance parsed in this process (see below) or calls `startEngineLoad()`. That spawns the `engine-load` thread, which reads the whole `.cin` (`DictionaryRepository.loadActive()`: user `active.cin` → built-in `assets/mrubyime.cin` → `assets/dicts/<name>.cin`) and builds the engine there, so service creation and the IME window do not block on 2.0 MB of IO. Main-thread work resumes in `onEngineReady(loadMs, id)` (sets `dictId`, metadata, layout rebuild); until then `@Volatile engineReady` is false and every main-thread path that would touch mruby returns early (the code box shows `…`). Cold load is **~1.7 s** for the full weighted uniliu table, measured on the phone (was ~2.6–2.9 s before the 2026-11-22 memory pass; `load=` covers the read *and* the parse). `MRB_ARY_LENGTH_MAX=0` in `build_mruby.sh` lifts mruby's 131,072 array cap (needed for `Hash#values` over the phrase table).
- **Memory profile of the loaded table (2026-11-22 measurements, Titan phone)**: the parsed structures cost ~92 MB native (was ~135 MB). The breakdown that matters: mruby `Hash#[]=` **duplicates unfrozen String keys** (hash.c:972), which used to leave every word as 3 string objects (@phrases value + @phrase_freq key + @words key) and every code as 2. The engine now (a) merges `@phrase_freq` into `@words` (`word → weight`, 0 = unweighted, plus an `@weighted` flag replacing the `@phrase_freq.empty?` guard), (b) freezes every word/code/char before storing so the hash keeps the object itself (−327k duplicate strings), (c) stores single-word `@phrases` buckets as the word String (Array only for the 742 genuinely multi-word codes), and (d) parses word-only `%phrase` lines by index with `getbyte`/`rindex` (no split array, no downcase probe per line). Result: −671k → −~560k live objects, load_dictionary live malloc 63.9 → 31.1 MB (host glibc measurement), device native heap −43 MB, host load 1078 → 756 ms, and zero `slow input` lines over a 60-key burst (the 30 ms spikes were GC marks over the old heap). `GC.start` at the end of `load_dictionary` plus one `mallopt(M_PURGE)` (resolved via dlsym; bionic declares it from API 26) in the JNI `init` hand the freed pages back. `MRB_WORD_BOXING` was measured (host) at **zero** additional saving on top of this — do not add it for size.
- **The parsed table is reused across service re-creation** (`EngineCache` in `MrubyimeIME`). The mruby state is a C static and `onDestroy` never tears it down, so switching to another input method and back (the case where the wait is felt) usually happens in the *same* process: `onCreate` compares `dict_id` + `DictionaryRepository.signature()` with what `EngineCache` recorded after the last successful load, and on a match resets the buffer, re-applies the metadata/max code length and skips the parse entirely — logcat: `engine reused (same process) id=… codes=… load=0ms` instead of `load=~2900ms`. The cache is recorded in `onEngineReady` and `reloadDictionary`; a new process starts empty and any id/signature mismatch (edited table, other `.cin`) falls back to a normal load. Do not "optimise" this away by clearing the cache in `onDestroy`.
- **The engine is generic `.cin`, not 嘸蝦米-specific.** `mrubyime_engine.rb` parses `%ename`/`%cname`, `%selkey`, `%keyname` (key → key-cap label), and `%chardef`. `@legal_keys` = `%keyname` keys ∪ every character that appears in a code (so 注音 can use digits, 行列 `;`/`/`, 大易 punctuation); `@table_max_code_len` = the longest code in the table. Class/file name is kept for JNI + prefs compatibility.
- Built-in **uniliu 萬國蝦米_unifont_t** table: 30,478 codes / 47,788 `%chardef` entries + a 139,637-line `%phrase` list (`詞 權重` → `entries` 187,422), `%selkey 0123456789`, longest `%chardef` code 5. `assets/dicts/` ships no table any more (`boshiamy.cin` was deleted); drop a `.cin` there to add one.
- **`%phrase` weights rank candidates; single-character words are ignored.** A word of length 1 is dropped in both forms **before** `derive_code` and before any weight bookkeeping, so the ordering of a code's own characters is exactly `%chardef`'s and a `%phrase` line can never reorder or duplicate them (`gns` → `妳 婃 你`, file order). A line's trailing pure-digit field is a frequency weight (`你好 121`); the parser strips it only when the line has ≥ 2 fields, so a word that *is* a number stays a word (`split_weight`). Weights go to `@phrase_freq[word]` (multi-char words only — ~100,149 in uniliu), `rank_by_weight()` stably sorts exact-code candidates heaviest-first within the char group and within the phrase group (never across them, so a phrase cannot displace the code's own characters), and `compose_candidates` sorts word-set → weight → code count. **Composition tries up to 3 characters per code** (`COMPOSE_CHARS_MAX` in `walk_segments`): 10,688 codes hold alternative characters (17,310 of 47,788 `%chardef` entries = 36 %), so using only `@table[code][0]` left 23,702 of 139,637 words (17 %) uncomposable and turned an alternative code into the wrong word (`wwnjn` → 違是). With K=3 composability is 98.6 % (K=2 95.7 %, K=4 99.5 %) for ~1.5× branching that the 40,000-step `@seg_budget` absorbs — host cost 0.4 ms at 5 codes, 1.0–2.3 ms at 10–140 for the two passes (device keeps every key under the 30 ms `slow input` threshold, measured up to a 64-code buffer). The first candidate still wins ties (the sort key ends with the per-code candidate index), so `pns` stays 你. **A half-typed last code is completed as well**: during the walk, `compose_candidates` records at most `TAIL_HEADS` (4) finished prefixes per split point (a Hash/array lookup per visited node, no scan), and `tail_readings` then appends the codes that turn each of those readings into a word the table already knows, taken from `@tail_index` (prefix → codes finishing it in ≤ `TAIL_LOOKAHEAD` (2) keys, one bucket ≤ ~57 codes, canonical-of-the-character codes first, `TAIL_CODES` 240 cap, `TAIL_MATCHES` 8 per head, `TAIL_MAX` 200 overall). So `pnsg` → **你好** instead of the literal 你機 (`g` alone is 機), `wwnj` → 這是, `gnsq` → 你們. Guesses are merged *after* the real readings, so they can never crowd them out. `@tail_index` is built once in `load_dictionary` (~14.4k slots, ≈ +50 ms host on the background `engine-load` thread). The walk runs in **two passes**, each with its own reading list and its own `TAIL_HEADS` heads: a canonical pass (one character per code, `SEG_BUDGET_CANON` = 3,000 steps) then the 3-character pass. A code that is also a prefix of the intended split otherwise eats the whole 120-reading cap first: `segnfooo` is `s|egn|fooo` (三峽區) but `seg` alone is a code (綏), and its subtree starved the `s` branch so the word never appeared. With the two passes **every code a character has** works — `segnfooo`, `segnfxx` (`s|egn|fxx`) and `segnfv` (the derived phrase key) all show 三峽區 first; on 240 sampled `%phrase` words typed with random non-shortest codes the word reaches the top 16 193 times (was 154, top-1 154 vs 115). `MAX_COMPLETIONS` is **16** now. `MrubyimeIME.onKeyPressed` logs `slow input: Nms buffer=…` (`Log.i`) only when a resolve takes ≥30 ms — that log is the trigger for adding P3 (incremental cache). `dedupe()` then removes repeats, because one `%chardef` char can sit under two codes and a char can also be a phrase. With no weighted lines the map is empty and the list is returned unchanged, so older/unweighted tables keep their order. Device evidence: `wr` → `0 測 1 测` (chardef order, no weight in play), `gnsgz` → `0 你好 1 妳好` (weight 121 > 妳好).
- Selection keys come from the active table's `%selkey` (`selkeys[i]`, absolute across the whole candidate row, so `9` can commit a candidate that is scrolled off-screen). 嘸蝦米's first candidate is key `0` even though the soft key row reads `1234567890`; a table with `%selkey 1234567890` shows `1` first.
- **`%selkey` may also be a radical** (注音 `%selkey 1234567890` + `1 ㄅ`, `2 ㄉ`, …; `%endkey 3467`). The engine keeps a prefix set (`@prefixes`) and exposes `would_extend?(key)` = `buffer+key` is itself a code **or** the prefix of a longer one. `MrubyimeIME.onKeyPressed` only lets such a key select a candidate when it can no longer extend the code: `2` → `28` → `284` builds ㄉㄚˋ while `284` then `1` picks candidate 1. A selection key that is **not** a legal code key (嘸蝦米 digits) always selects as before. A selection key with no matching candidate is swallowed (never fed to the engine) so the composition survives. A digit that is **not** a legal key and has no composition is committed as plain text.
- Soft keyboard & bar modes (5 key rows in both modes, 12-column grid):
  - **Row layout** (DSL pages, 12 keys per row): ① `1 2 3 4 5 6 7 8 9 0 - =`; ② `q w e r t y u i o p [ ]`; ③ `a s d f g h j k l ; ' \`; ④ `z x c v b n m , . /` + 倒引號 (backtick) + `⌫`; ⑤ `中/英` (span 2) + Space (span 8) + `⏎` (span 2).
  - **Swipe-up symbols**: row 1 → `! @ # $ % ^ & * ( ) _ +`; `[` `]` `;` `'` `\` `,` `.` `/` and 倒引號 → `{ } : " | < > ? ~`. The target is also printed as the key's `sub_label` (top-right), so the gesture and the corner label always agree. Letter keys send the uppercase letter on swipe-up (in Chinese mode that is the same as the tap, so their `sub_label` is blank).
  - **Chinese mode**: rows 1–4 show **uppercase** letters (`transform: :upper`). The bar is code box (weight **2**) + candidate scroll (weight **9**) + hide `▼` (weight **1**) = 12 units. `, . ' [ ]` (the legal punctuation radicals) live on the letter rows and enter composition like hardware keys (452 codes start with `,`); `; \ /` and 倒引號 are plain-text commits.
  - **English mode**: rows 1–4 show **lowercase** letters (no `transform`). The bar becomes a **12-key action bar**, each key weight 1: `TAB` (`key_event`), a blank `noop` key, `^A` `^C` `^V` (`clipboard` → `performContextMenuAction`), `⇧ ⇩ ⇦ ⇨` (`key_event` up/down/left/right), `DT` (`datetime`), `W` (`weekday`), and hide `▼`. No buffer, no candidate row.
  - Mode switching is the row-5 `中/英` key (`toggle_mode`), Space swipe-down (>30 dp) or the hardware hotkey **Alt+Space / Shift+Space**. A bare Shift is now an ordinary modifier. The row-5 key shows the **current** mode (`中` on the Chinese page, `英` on the English page).
- `MrubyimeEngine#input`: lowercases and **appends** to the buffer (never truncates), but **stops resolving candidates once the buffer is past the current max code length** (`@max_code_len`, reset to the table's longest code on load, overridden over JNI by `set_max_code_len` — table max when 「最大碼清空組字」 is on, 140 when off). Auto-commit lives in `MrubyimeIME.onKeyPressed`, not in Ruby: `buffer.length >= min(4, table max) && candidates.size == 1 && !engine.canExtend()`. `can_extend?` checks every legal key, so a 4-code prefix of a 5-code is not committed.
- **Dead-code auto-clear**, two independent gates in `MrubyimeIME.onKeyPressed`:
  1. **「死碼清空編碼區」** (`clear_dead_code`, default **false**): a **1–3 char buffer with no candidates AND `engine.deadPrefix()` is true** is cleared, where `dead_prefix` checks whether **adding ANY one of the active table's legal keys** (`@legal_keys`) still yields nothing (`@table[buffer + k]` empty for all k). So a prefix that can still grow to a valid code is preserved (e.g. `aad` → `aadb`/`aadk`/`aado`; `,,` → `,,f`). Note the trial only looks **one key ahead**. `dead_prefix` is read-only (never touches the buffer). When the switch is off, a dead prefix is left untouched. **Auto-composition keeps most buffers alive**: `dead_prefix` returns false as soon as `compose_word(buffer)` succeeds, and any buffer that reads as a run of single-char codes composes, so with the built-in table `zzzz`/`qqqq`/`a'` all have candidates and are never cleared — the switch only catches leftovers that cannot segment.
  2. **「最大碼清空組字」** (`max_code_clear`, default **false** → max code 140): once the buffer reaches the current **max code length** (the active table's longest code when on, 140 when off) with no candidates it is cleared. With the switch **on** (嘸蝦米: 5) a 5-code dead code wipes the box; with it **off** (max 140, the default) the buffer keeps growing and the code box shows only the **last 6 codes** (`updateBuffer` `takeLast(6)`), the engine still holding the whole buffer.
- Candidates cross JNI as one `\n`-joined string (`inputSerialized`); the `jobjectArray` variants were removed. Keep the serialized pattern.

## JNI / UTF-8 rules

- Output: `utf8_to_jstring` (`NewByteArray` + `new String(bytes,"UTF-8")`). Never `NewStringUTF` for non-ASCII (SKILL Rule B).
- Input: dictionary and keys cross JNI as `ByteArray` (raw UTF-8) and become mruby strings via `mrb_str_from_jbytes`; never `GetStringUTFChars` (Modified UTF-8).
- Wrap every call in `mrb_gc_arena_save/restore`; check `mrb->exc` after every `mrb_funcall` and drain it with `log_mrb_exception`.
- The engine lives in a C static: `mrb_gc_register` it after `mrb_obj_new`, or GC may collect it between calls.
- JNI surface is exactly `init(ByteArray)`, `inputSerialized(ByteArray)`, `backspaceSerialized`, `currentCandidatesSerialized`, `selkeys`, `buffer`, `reset`, `tableSize`, `deadPrefix`, `setMaxCodeLen(Int)`, `reloadDictionary(ByteArray)`, `legalKeys`, `keynamesSerialized`, `dictionaryName`, `tableMaxCodeLen`, `entryCount`, `canExtend`, `wouldExtend(ByteArray)`, `layoutSerialized(ByteArray ctx)`, `layoutFromSourceSerialized(ByteArray source, ByteArray ctx)` — 20 functions (the user-engine entry points were removed together with user engines). Kotlin externals (`MrubyimeJNI`), delegate interfaces (`MrubyimeEngineDelegate`, `MrubyimeEngineDelegateImpl`), and C symbols must stay in sync; mismatches only show up at runtime. `reloadDictionary` calls the Ruby `load_dictionary` on the live engine (no `mrb_close`/`mrb_open`), so the table, key names and buffer are replaced atomically; the Kotlin side falls back to `builtin:mrubyime` if `tableSize()` comes back 0. `legalKeys` / `keynamesSerialized` / `dictionaryName` / `tableMaxCodeLen` / `entryCount` / `canExtend` expose the generic table metadata to the policy layer. `currentCandidatesSerialized` calls the Ruby `current_candidates_serialized` (peeks `@table[@buffer]` **without** touching the buffer) and exists so a mode switch can re-query the preserved composition. `deadPrefix` calls the Ruby `dead_prefix`, a read-only peek used by the 1–3 code dead-prefix clear (see above). `setMaxCodeLen` calls the Ruby `set_max_code_len` to flip the engine's max code length (the active table's longest code / 140) from the 「最大碼清空組字」 switch.
- Layout JNI: `init()` loads `engine_irep.c` + `keyboard_dsl_irep.c` + `keyboard_layout_irep.c` into the shared `mrb_state`, which defines the top-level `keyboard_layout_serialized(ctx)`. `layoutSerialized` calls it with a flat `key=value\n` context (mode/theme/density/editor fields) and returns the IR JSON. `layoutFromSourceSerialized` evaluates an imported DSL in a **throwaway `mrb_state`** (`mrb_open` + `mrb_load_irep(keyboard_dsl_irep)` + `mrbc_context`), caps the source at **64 KB**, and never touches engine state. Both strings cross JNI as `ByteArray` (UTF-8).
- **Imported-DSL errors are reported with line/column**: `layoutFromSourceSerialized` returns the IR JSON on success, or `"\u0001" + message` on failure (`LAYOUT_ERROR_PREFIX`; JSON never starts with 0x01). The sandbox parses with `mrb_parse_nstring` under a `mrbc_context` whose `capture_errors = TRUE` and `filename = "keyboard.rb"` (set via `mrb_ccontext_filename` — never assign `cc->filename` directly: `mrbc_context_free` frees it, aborting with "Pointer tag … truncated"). `capture_errors` is what makes the parser record `lineno`/`column`/`message` in `p->error_buffer` (up to 10, we print 3) instead of `fprintf`-ing `line N:C: …` to stderr (lost on Android) and raising a bare `"syntax error"`. Runtime errors append the first backtrace frame, e.g. `undefined method 'foo' (keyboard.rb:8:in instance_exec)`. Kotlin surfaces this via `KeyboardLayoutRepository.validateSource()` / `validateSourceDirect()` → `LayoutSourceResult(layout, error)`; the settings screen turns `line 6:20: …` into `第 6 行（第 20 欄）` plus the offending source line (`describeLayoutError`). Always check `st->exc` after `mrb_load_irep` / parse / exec and re-raise it, or the later `keyboard_layout_serialized` call masks the real error with `no layout has been defined`.
- **The sandbox must run inside `mrb_protect_error`**: user code is untrusted and mruby raises parse/runtime errors with `mrb_exc_raise`, which `abort()`s the process when no protect frame is installed. This build has no `mruby-error` gem, so the core `mrb_protect_error(mrb, body, void*, &error)` is used (not `mrb_protect`). The caught exception object is returned in the result value (and `mrb->exc` is cleared), so the message is logged from `result`.
- Host `mruby` 3.3.0 (the `host` build made by `build_mruby.sh`) lacks `MRB_UTF8_STRING` (device build has it), so host-side CJK `length`/`[]` are wrong. For a host build with the **same feature set as the device** (UTF-8 strings, `MRB_ARY_LENGTH_MAX=0`, big GC arena, `mruby-io` + `mruby-time` for profiling) use the committed `mruby/host_test_config.rb`:
  ```bash
  cd mruby && rake MRUBY_CONFIG=host_test_config.rb   # → build/host-test/bin/{mruby,mrbc}
  cat ../app/src/main/mruby/mrubyime_engine.rb /tmp/prof.rb > /tmp/run.rb
  ./build/host-test/bin/mruby /tmp/run.rb
  ```
  Host timings are ~5× faster than the phone but track it proportionally (full uniliu load: ~1.0 s host / ~2.6 s device with the current weighted one-entry-per-line table), so profile on the host and only confirm on the device. **The 139,637-line `%phrase` block is ~85 % of that**: on the host, `%chardef` alone is ~0.15 s, the same words repacked 100 per line ~0.50 s, one-word-per-line without weights ~0.83 s, and the shipped file ~1.09 s. Skipping single-char `%phrase` words before `derive_code` removed ~21k derivations (host 1.15 s → 1.09 s, device ~3.0 s → 2.77 s); the tail index (P1) adds back ~50 ms host (1093–1141 ms measured) on the background load thread. The in-place `@phrases[pc] << w` / `if list … else @phrases[pc] = [w]` form (no fresh `[]`, no redundant hash store per word) is still worth keeping. There is no parse-result cache; `EngineCache` only avoids re-parsing inside one process.

## Replaceable `.cin` table (`DictionaryRepository` / `CinTable`)

- Sources and ids: `builtin:mrubyime` → `filesDir/dicts/mrubyime.cin` when it exists and is sane, else `assets/mrubyime.cin` (uniliu); `builtin:<name>` → `assets/dicts/<name>.cin` (none ship by default); `user:active` → `filesDir/dicts/active.cin`. The selected id lives in the existing `mrubyime_settings` prefs as `dict_id` (default `builtin:mrubyime`); an id that no longer resolves falls back to the default. The Settings list label is read from the asset's `%cname`.
- **Editable copy of the built-in table**: `dicts/mrubyime.cin` (canonical `filesDir/dicts/`, mirror `Android/data/<pkg>/files/dicts/mrubyime.cin`) is seeded from the asset by `DictionaryRepository.seedBuiltinCopy()` — atomic temp+rename, run on the `engine-load` thread, exactly like `layouts/keyboard.rb`: missing → write; untouched seed (`sha256` == the recorded hash) → refreshed when the APK ships a new table; edited → never overwritten (`imported mrubyime.cin from Android/data` / `builtin copy was edited by the user, leaving it alone` in logcat, tag `MrubyimeDict`). An edited copy **is** what `builtin:mrubyime` loads, so an MT-Manager-style edit takes effect on the next keyboard show. Guard rails: `read()` uses the copy only if `looksLikeCin()` sees `%chardef`/`%cname`/`%ename` in the first 64 KB, and `reloadDictionary()` falls back to the shipped asset (not to the same id) when `tableSize()==0`. 「恢復內建碼表」 deletes the copy as well, so the shipped table comes back.
- User table mirror: `getExternalFilesDir(null)/dicts/active.cin`; `sync()` copies a newer mirror back to the canonical file. `signature()` = id for built-ins, `id:size:mtime` for the user file; `MrubyimeIME.onStartInputView` compares `dict_id` + signature and calls `reloadDictionary()` on change (also covers an external editor writing the mirror while the IME stays alive).
- Import: settings 「輸入法碼表（.cin）」 → `ACTION_OPEN_DOCUMENT` (`*/*`), max 4 MB, `CinTable.parse` must find at least one `%chardef` line. `saveUser` writes a temp file then renames, mirrors to Android/data, and sets `dict_id=user:active`. Export uses `ACTION_CREATE_DOCUMENT` with `text/plain` and a `<base>.cin` name. 「恢復內建碼表」 deletes the user file + mirror and resets the id.
- `CinTable` is a **lightweight header parser** used only by Settings (name, `%selkey`, keynames, unique code count, entry count, max code, legal key chars). The authoritative parser is `mrubyime_engine.rb`; do not let the two drift on `%keyname`/`%chardef` whitespace handling (both split on the first whitespace run).
- Keyboard labels: `KeyboardView.setDictLabels(map)` applies `%keyname` labels in Chinese mode only, and only when the label is **not** a trivial variant of the key (`a → Ａ`, `, → ，`, `' → ’`, `[ → 〔` are skipped; `a → 日`, `1 → ㄅ` are applied). The built-in `builtin:mrubyime` always passes an empty map, so the classic A-Z look is unchanged.
- **Long labels** are handled by the per-key DSL option `label_fit:` (`KeySpec.labelFit`) — `:wrap` (break every `label_wrap` glyphs, default 2), `:shrink` (keep one line, reduce the font via `fitShrinkLabels()` after layout), `:none` (leave as written). Table `%keyname` labels default to `:wrap`, DSL labels to `:none` (so `TAB`/`DT` never break). `applyModeLabels()` sets the text + `isSingleLine`/`maxLines`, then `updateKeyFontSizes()` (size by line count) and `fitShrinkLabels()`. Every key label lives in a cell-sized `KeyFrameLayout` (a `FrameLayout` with `clipChildren=true`, `KeyboardRenderer.createKeyView`) so a label that can't fit is **clipped to its cell** instead of spilling into the neighbour; the same container carries the visual gap insets.
- Built-ins can be added at build time by dropping `<name>.cin` into `assets/dicts/` (see `assets/dicts/README.txt`); no Kotlin change is needed. `assets/dicts/README.txt` is not `.cin`, so it is ignored by `assets.list()`.

## User-editable layout (`KeyboardLayoutFiles`)

- `layouts/keyboard.rb` is an optional user layout in the same DSL. Load order in `KeyboardLayoutRepository.load()`: **keyboard.rb → built-in runtime DSL (`keyboard_layout_irep.c`) → `assets/keyboard_layout.json` → emergency layout**. A file that fails the 64 KB cap or the JNI sandbox is logged and skipped, never fatal.
- Storage lives in `KeyboardLayoutFiles`: **canonical `filesDir/layouts/keyboard.rb`** (root/Shizuku reachable) plus an **Android/data mirror** `getExternalFilesDir(null)/layouts/keyboard.rb`. `sync()` reconciles them — newer wins, and a mirror-only file is imported when it validates (an invalid mirror is left alone). It is called from `load()`/`activeSource()` and from `MrubyimeIME.reloadLayoutIfChanged()`.
- Live reload: `MrubyimeIME.onStartInputView` calls `reloadLayoutIfChanged()`, which syncs, compares `KeyboardLayoutFiles.sourceSignature()` (mtime+size) with the signature the current view was built from, and on change calls `KeyboardView.setLayout()` — this rebuilds the IR view tree once (not per keystroke) and re-applies theme/size/fonts/padding.
- Settings 「鍵盤佈局（ruby dsl）」 section (`card_layout`): 匯入 (.rb) (`ACTION_OPEN_DOCUMENT`, MIME `*/*` so any extension — `.rb`, `.rb.txt`, `.txt` — can be picked), 匯出 (`ACTION_CREATE_DOCUMENT`, suggested name `keyboard.rb`, MIME **`text/x-ruby`**: with `text/plain` the Downloads provider appends `.txt` and the file lands as `keyboard.rb.txt`; `text/x-ruby` is unknown to `MimeTypeMap`, so the `.rb` name is kept intact), 寫入編輯目錄, 恢復內建佈局, 用外部編輯器開啟 (FileProvider `content://com.example.mrubyime.layouts/keyboard.rb`). Import validates through `KeyboardLayoutRepository.fromSourceDirect()` before it overwrites anything. Whatever the picked file is named, it is stored as `layouts/keyboard.rb`.
- **SAF / DocumentsUI** (`LayoutDocumentsProvider`, authority `${applicationId}.documents`): a `DocumentsProvider` with **exactly one root that opens straight into `Android/data/<pkg>/files`** (`getExternalFilesDir(null)`, falling back to `filesDir` when external storage is unavailable), i.e. the folder a file manager (MT Manager, Material Files) sees on disk:

  ```
  Android/data/com.example.mrubyime/files/
    layouts/keyboard.rb     fonts/<name>.ttf
    dicts/active.cin        dicts/mrubyime.cin (editable copy of the built-in)
    sounds/<name>.ogg
  ```

  The IME keeps its working copies in `filesDir/…` (that is what it reads); a write made here is pulled in by the `*.sync()` calls on every keyboard show, and `createDocument`/`deleteDocument`/`renameDocument` propagate immediately (they also rename/delete the working copy, or the newer-wins sync would resurrect it). Document ids are `f:<path relative to the root>` with `/` separators; `canonicalPath` + prefix check rejects `..`/symlink escapes. Manifest: `android:permission="android.permission.MANAGE_DOCUMENTS"`, `exported=true`, `grantUriPermissions=true`, intent-filter `android.content.action.DOCUMENTS_PROVIDER`. Debug: `adb logcat -s MrubyimeLayout` (`onCreate`, `queryRoots`, `root=…`).
  - **Root flags**: `FLAG_LOCAL_ONLY or FLAG_SUPPORTS_CREATE or FLAG_SUPPORTS_IS_CHILD`. `COLUMN_MIME_TYPES` must stay **unset** — declaring it makes DocumentsUI drop the root from `*/*` pickers ("Excluding root … unsupported content types"). `FLAG_SUPPORTS_IS_CHILD` is **mandatory for the folder picker**: DocumentsUI's `ProvidersAccess.getMatchingRoots` filters with `state.action == ACTION_OPEN_TREE && !root.supportsChildren()`, so without it the root only shows in *file* pickers and a file manager (which needs `ACTION_OPEN_DOCUMENT_TREE` to obtain a persisted folder grant) never sees it. We do implement `isChildDocument()`, so the flag is truthful. Verified on device with `adb shell am start -a android.intent.action.OPEN_DOCUMENT_TREE`: the drawer lists 「小蝦米輸入法 → Android/data/com.example.mrubyime/files」 and 「使用這個資料夾」 is enabled (the internal-storage root shows 「無法使用這個資料夾」).
  - **`onCreate` order matters: sync before seed.** `KeyboardLayoutFiles.exportBuiltin` rewrites *both* the canonical file and the Android/data mirror, so seeding first silently discards an edit made only in Android/data (`adb push` + `touch`, or a file manager writing there) while the canonical was still the pristine seed. The seed functions `sync()` first, and provider `onCreate` runs `KeyboardLayoutFiles.sync` / `DictionaryRepository.sync` before the seeds.
- Debugging a bad user layout: `adb logcat -s MrubyimeJNI MrubyimeLayout MrubyimeIME` (the sandbox logs "mruby exception: …" on `MrubyimeJNI`, failed imports on `MrubyimeLayout`).
- No new storage permission is required: `getExternalFilesDir` is app-scoped, SAF returns a per-file grant, and the DocumentsProvider is protected by `MANAGE_DOCUMENTS` (system-only). `MANAGE_EXTERNAL_STORAGE` is deliberately **not** used.

## User engines — REMOVED (size pass)

- The whole user-Ruby-engine feature (`engine/engine.rb`, `EngineFiles`, `EngineCheckService`/`EngineCheckClient` with their `:enginecheck` process, the settings 「輸入法引擎（mruby）」 card, and the JNI entry points `initFromSource`/`engineFromSource`/`engineReset`/`engineIsUserDefined`/`engineLastError`/`engineValidate`) was **removed** to shrink the APK. The engine always runs the compiled bytecode (`engine_irep.c`); its source lives at `app/src/main/mruby/mrubyime_engine.rb` (build-time only). An old install's leftover `filesDir/engine/engine.rb` is simply ignored dead data.
- The engine contract is unchanged — **`class MrubyimeEngine` instance methods**: `load_dictionary(data)`, `input(key)`, `input_serialized(key)`, `current_candidates_serialized`, `backspace`/`backspace_serialized`, `reset`, `table_size`, `entry_count`, `selkeys`, `buffer`, `legal_keys_serialized`, `keynames_serialized`, `dictionary_name`, `table_max_code_len`, `can_extend?`, `would_extend?(key)`, `dead_prefix`, `set_max_code_len(len)` — C calls the instance directly.
- `buildEngine(dict)` (on the `engine-load` thread) is now just `engine.initDictionary(dict)` followed by `DictionaryRepository.seedBuiltinCopy(this)`. `onStartInputView` no longer hot-swaps engines; it only reloads the **layout** and the **table**.
- Device mruby gotchas that still matter:
  - **Never write `@table[c] ||= []`** in the engine source — the `||=` on a `Hash#[]` receiver mis-dispatches at runtime (`undefined method 'ar'`/`'MAX'`/`'bsearch_index'`, wrong line numbers). Use a temp var: `list = @table[c]; list = [] unless list; list << x; @table[c] = list`. The engine is already written this way.
  - **GC arena overflow**: loading a large `.cin` in one call overflows the default 100-slot arena → random `undefined method '…'`. The device libmruby is built with `MRB_GC_ARENA_SIZE=4096` (`build_mruby.sh`) and `engine_build_body` wraps `load_dictionary` in `mrb_gc_arena_save/restore`.
  - The layout DSL is loaded **after** the engine in `engine_build_body`.
  - The minimal gembox does **not** include `Set`/`Fiber`/`Enumerator`/`Time`/`Struct`/`Data`/`Pack`/`Random`/`ObjectSpace`; don't reach for them in engine or DSL code.

## Keyboard view invariants (`KeyboardView` / `KeyboardRenderer`)

- `MrubyimeIME.onCreateInputView` loads the layout (`KeyboardLayoutRepository`: runtime engine JSON → `assets/keyboard_layout.json` → small emergency programmatic layout), then builds **two per-page subtrees** (bar + rows) into `key_bar` (`FrameLayout`) and `key_rows`. Only the active page is visible; duplicate ids across pages are safe because every lookup goes through per-page references (`RenderedKeyboard.pages`). `view_keyboard.xml` is **not inflated** any more; it only supplies the `R.id.*` constants.
- The built-in Chinese/English pages are one DSL file (`keyboard_layout.rb`) on a **12-column** grid; the Chinese bar weights are `buffer 2 | candidates 9 | hide 1` (all `weight:`, so they split the bar proportionally and `▼` keeps exactly 1 unit) and the English bar is 12 keys of weight 1. The English page replaces the whole bar (no buffer/candidate row).
- Geometry is `KeyRowLayout`: `span` = fixed share of the `columns` grid, `weight` = flex share of the leftover, `align` = `start`/`center`/`end`/`space_between`. **Positions come from the grid, not from the previous key's edge**: `unit = (width − 2·outer)/columns` and every edge is `round(outer + cumulativeSpan·unit)`. Rows with different key counts/spans therefore land on the *same* seams (per-key `toInt()` truncation used to drift a pixel or two per key — that is why mixed rows looked misaligned). Gaps are **visual only** for key rows: `KeyFrameLayout` keeps the full grid cell as touch bounds and insets the plate/label by `gap/2`, and `RowsLayout` gives each row half of `gap_v` (its touch band includes the seam), so tapping a gap still hits the nearest key. Horizontal gap = `grid gap_h` (per-row `gapH` overrides), vertical gap = `grid gap_v`, outer inset = `grid outer`. The bar/status rows keep the legacy narrowed bounds (`KeyRowLayout.touchContiguous = false`). The **built-in layout sets all of them to 0**, so keys are flush — the only separation left is the 1 dp `keyBorder` outline (Light Mode black `#000000`, Dark Mode `#1C1C1E`). A row whose spans do **not** sum to `columns` leaves the deficit to `align`. All of these are **dp** values (converted with `px()`), not grid units. Parser defaults when omitted: `gapH/gapV = 1` dp, `outer = 0.5` dp.
- **Implicit padding is not the cause of gaps**: key containers are measured `EXACTLY` by `KeyRowLayout`, so a label `TextView`'s padding/`minWidth` cannot shift the grid. The only intentional inset is `KeyFrameLayout.setVisualInsets()` (half the DSL gap) on the key container; to control spacing use the DSL grid/bar/group gap values, not view padding.
- Candidate chip styling: text is **24sp bold, formatted `n字`** (index immediately followed by the glyph — no space, no brackets). The engine returns up to **16** candidates; only the first `selkeys.length` (10) get a key label, and the rest render as the bare word (no `10字`) so a chip never grows past the others. **Every chip renders the same shape and carries `minimumWidth` = width of `0微`** (measured with its own 24sp bold paint, + PadH of 3dp) so all cells share one width and the selection cue never changes size; candidates past the tenth are reachable by tap, scroll or D-pad, not by a `%selkey` digit. The border comes from the DSL: `candidates border:` frames every chip and `border_selected:` the active one; the **built-in** declares `border: { width: 1, color: :seam, style: :dotted }` (a subtle dotted frame; seam is white in Light so it is invisible there and visible in Dark) and `border_selected: { width: 2, color: :ink, style: :solid, side: :bottom }` (the 2 dp selection rule, white on `#3A3A3C` / black on white). `paintChip()` picks `border_selected` for the active chip and `border` for the rest; a layout that omits both falls back to `chip_hash`'s legacy `selected.border: { bottom: 3 }` (3 dp bottom rule). A legacy `{ bottom: … }` hash has no `side`, and `parseBorder()` deliberately defaults **that** form to `side="bottom"`; a `{ width: … }` hash defaults to `side="all"`. `BorderedPlateDrawable` (own file) is the only thing that can draw dashed/dotted strokes — `GradientDrawable.setStroke()` is solid-only — so `bar border:` and both chip borders go through it. The Chinese placeholder chip is painted with the same `border_selected`, so it matches the real selection cue.
- Buffer code styling: **24sp bold** (same size as the chips), uppercase, **no frame** (plain `#3A3A3C` plate in Dark Mode / white plate in Light Mode), box width **2 units** in the built-in layout (`buffer weight: 2`). `KeyboardView.bufferWidthWeight` is the settings override: **`0` = follow the layout** (default, `buffer_width_follow_layout=true`), a positive value replaces the buffer weight and the candidate row takes the rest of the `buffer + candidates` budget, so `▼` never shrinks. When 「最大碼清空組字」 is off and a long code is typed, the box shows only the **last 6** (`updateBuffer` `takeLast(6)`) and `ellipsize="start"` trims anything longer. Tapping the box commits the raw code (`onCommitBuffer`); swiping **up** on it commits exactly what the inline composing display shows (`onCommitInlineComposing` → `inlineComposingText()`, e.g. `會 ＡＤ` in mode 7, falling back to the raw code when inline display is off).
- **Buffer and chip text share one baseline**: both set `includeFontPadding=false`, and the chips also call `setFallbackLineSpacing(false)` (API 28+) — without it the CJK fallback font inflates the chip line box and its baseline lands ~6 px below the Latin-only buffer ("一高一低").
- Keys are `TextView`s created by `KeyboardRenderer` from `KeySpec`: a key's `id`/`role` (`buffer`, `candidate_row`, `backspace`, `space`, `space_alt`, `enter`, `hide`, `dpad_*`, `select_all`/`copy`/`paste`) drives view ids; its `action` drives wiring in `KeyboardView.dispatchAction`. **Every key action goes through one dispatcher**, shared by taps, `long_press`, and `gestures:`:
  - `code` (+`value`, defaults to the label's first char) → commit that char
  - `space`, `enter`, `backspace`, `ime_hide`, `noop`
  - `toggle_mode` → `listener.onToggleMode()` (flips 中/英 exactly like the Space swipe-down)
  - `combo` + `value: "ctrl+shift+1"` (also `alt+tab`, `ctrl+a`, `shift+space`…) → `MrubyimeIME.sendKeyCombo()` sends DOWN/UP with the meta state; a lone modifier (`"ctrl"`) is sent as a physical modifier tap
  - `key_event` + `value: "ins"|"del"|"home"|"end"|"pgup"|"pgdn"|"tab"|"capslock"|"esc"|"menu"|"f1".."f12"|"up"..` → same sender as `combo` (no modifiers needed); `keyCodeFor()` in `MrubyimeIME` is the single name table
  - `modifier` + `value: ctrl|shift|alt|meta` → **sticky latch** (`KeyboardView.modifierLatch`): the label gets `UNDERLINE_TEXT_FLAG`, the next `code`/`combo`/`key_event` is sent as a combo, then the latch clears
  - `date`/`time`/`weekday`/`datetime` (+ optional `value:` = `SimpleDateFormat` pattern) → `listener.onCommitText(formatted)`; the value is taken **at tap time**, not at layout load
  - `dpad` + `value: up|down|left|right`, `clipboard` + `value: select_all|copy|paste`
  - `gestures: { swipe_up: "W", swipe_down: :toggle_mode }` → per-key swipe actions (a bare **String** means "commit this text", a symbol means that action, and a hash is an action either as `{ action: :combo, value: "shift+enter" }` or the short IR form `{ a: :combo, v: "shift+enter" }`); tap still runs `action`. When `gestures` is present the automatic English letter swipe-up is not attached. The built-in ⏎ key uses `swipe_up: { action: :combo, value: "shift+enter" }`.
  - `long_press` currently supports **only** `toggle_hide_rows` (▼); any other value is consumed and does nothing (`KeyboardView.wireKey` has a single `when` branch).
- **Corner label**: when a key has `sub_label:` the renderer wraps the centred label in a `FrameLayout` and puts a smaller `TextView` at the top-right (`KeyView.subLabelView`). `applyTheme()`/`updateKeyFontSizes()` must colour/size `kv.label` (and `kv.subLabelView`) — not `kv.view`.
- **Per-key text alignment** (`align: :left/:center/:right` on a key) is applied by the renderer as the label's `gravity` (+8 dp horizontal padding); it does not affect geometry. **Row alignment** is `row align:` (`:left/:start`, `:center`, `:right/:end`, `:space_between`) and only matters when the row's spans sum to **less** than `columns` — the deficit is placed according to the alignment.
- **Mode labels**: `label_zh`/`label_en` (+ `sub_label_zh`/`sub_label_en`) make one key change its text with 中/英 mode. `KeySpec.textFor(english)` applies `transform:`; `KeyboardView.applyModeLabels()` runs on every `render()` (so `toggle_mode`, Space swipe-down, hardware Alt+Space/Shift+Space and `setEnglishMode()` all refresh it). The **action is not swapped** — a `code` key must declare `value:` explicitly.
- **Key sound / haptic**: `sound :click, volume: 0.6` at layout level (`KeyboardLayout.sound`) and `sound:`/`sound_volume:` per key (`KeySpec.sound`). Played in `dispatchAction` from `playKeySound()`: `click`/`system` → `AudioManager.playSoundEffect`, anything else → `SoundPool` loading `assets/sounds/<name>`, `assets/<name>`, an **absolute path**, then `filesDir/sounds/<name>` (preloaded by `preloadSounds()` in `setLayout()`). `haptic: :light/:medium/:heavy` calls `performHapticFeedback`. Default is silent (no `sound` token → nothing), so old layouts are unchanged.
- **Status lamps**: `bar do … status span:, gap: (dp) do lamp :caps/:shift/:ctrl/:alt/:meta/:english/:latch/:buffer/:candidates, label:, span:, on_ink:, off_ink: … end` → `StatusSlot`(`LampSpec`) in the IR, rendered by `KeyboardRenderer.createLampView()` into a nested `KeyRowLayout` and collected per page as `PageViews.lamps` (`LampView`). They are **not** `KeyView`s: no click, no dispatch, no `keyViews` entry. `KeyboardView.render()` → `refreshStatusLamps()` → `updateStatusLamps()` is the only repaint path; `applyTheme()` and the `hardwareModifiers`/`capsLockOn` setters also call it. Lit state = `lampStateOn()` (physical `hardwareModifiers` from `MrubyimeIME.updateHardwareModifiers()` on `onKeyDown`/`onKeyUp` **or** the sticky `modifierLatch`; `capsLockOn` from `KeyEvent.isCapsLockOn`; buffer/candidates/mode from the view state). Lit ink = `lampOn` → `ink`; dim = `lampOff` → `keyBorder` → `ink`, blended 35 % toward the bar plate (`blendArgb`), so a lamp token only needs to be the *dark ink* and works in both themes. Lamp text is 11 sp bold, `includeFontPadding=false`.
- **Seam lines are drawn per side**: `KeyboardView.gridKeyDrawable()` builds fill + right + bottom strips, plus left (first column) / top (first row) via `KeyView.borderLeft`/`borderTop`. Flush neighbours therefore show **one** 1 dp seam instead of two stacked borders (~2 dp). Never go back to a full `setStroke()` per key: that is what made the internal lines look twice as thick as the outer edge.
- **DSL surface actually wired**: `buffer` honours `span`/`weight`/`format`/`max_chars`/`role`/`id`/`font: { size:, weight:, family: }` (`style:` is parsed but unused); `candidates` honours `span`/`weight`/`role`/`id`/`font: { size:, weight:, family: }`/`chip_style`/`border:`/`border_selected:` (`BarBuilder#chip_hash` defaults the chip font to 24 sp bold and merges `Keyboard.border_hash(opts[:border])`/`border_selected` into `style.border`/`style.selected.border`; the renderer re-applies the bar gap / padH / min-width reference); `bar` honours `height`/`bg`/`gap`/`align`/`border:` (`BarBuilder#initialize` reads `opts[:border]`, emitted as `BarSpec.border` — **drawn inset**, painted on each page's `barContainer` background since that is the layer covering the bar plate, with each container padded by **its own** border width so the content and the grid shift inwards and the frame is never clipped; the built-in uses `border: { width: 1, color: :ink, style: :solid, side: :top }` on **both** pages — Chinese and English); `key` honours `span`/`weight`/`role`/`label*`/`sub_label*`/`action`/`value`/`align`/`transform`/`flat`/`ink`/`bg`/`style`/`desc`/`sound*`/`haptic`/`gestures`/`long_press`/`repeat`/`font: { size:, weight:, family: }` (`icon:` is parsed but not rendered); `min_touch`, `theme … state` and `candidates autoscroll:` are parsed but unused. Only the **first page** (`defaultPage`) and a page named `english`/`en` are ever shown (`RenderedKeyboard.showPage`).
- Adding/removing a key = edit `keyboard_layout.rb`; do not hand-add views to the XML.
- **Fonts (`font: { family: "…" }`)**: `FontStore.typefaceFor(context, family)` resolves a file name (extension optional) in `assets/fonts/`, `filesDir/fonts/`, the Android/data `files/fonts/` mirror, then as an absolute path; a miss is cached as `null` (system typeface) and logged on `MrubyimeFont`. `FontStore.ensureDirs()` runs in `MrubyimeIME.onCreate`, and `FontStore.clear()` runs in `KeyboardView.setLayout()` so a font copied in later is picked up. Applied to the buffer, the candidate chips, key labels and sub-labels; `font: { size:, weight:, family: }` is honoured everywhere `font:` is.
- Candidate bar (48 dp default) layout: Chinese = buffer → `StepScrollView` chips → punctuation group `, . ' [ ]` → hide `▼`; English = 19 symbol keys → hide `▼`. There is no pagination, page number or arrows.
- No pagination: `updateCandidates()` renders **all** candidates into one `StepScrollView`, labels are absolute `selkeys[i]`, and it scrolls the selected chip into view (`scrollTo(selectedChip.left)`). The row scrolls in **full-page steps** (`StepScrollView`: follows finger with `scrollBy` on ACTION_MOVE, eases onto page boundary with `smoothScrollTo` on ACTION_UP, and loops across page boundaries).
- Selection cue & placeholder: the selected chip gets `border_selected` (the built-in: a **2 dp bottom rule**, white in Dark Mode / black in Light Mode) plus the theme's ink colour. When there is **no candidate**, an **empty placeholder chip** (`createPlaceholderChip(framed)`) is shown: it is painted with the same `border_selected` in Chinese mode and is plain (no border) in English mode, so switching modes repaints it (`placeholderFramed`/`styledTheme` guard).
- Chip reuse: `updateCandidates()` keeps one `TextView` per candidate and only adds/removes the delta, swaps `text` when changed, and repaints a plate only when selection index or theme changes (`styledSelection`/`styledTheme`). The same `text`-changed guard covers `updateBuffer()`, so a keystroke does not repaint the whole keyboard.
- Gestures: Space tap commits selected candidate / buffer; Space swipe-down (>30 dp) and the hardware hotkey **Alt+Space / Shift+Space** toggle Chinese/English; Space swipe left/right moves the text cursor one character per ~24 dp (`onMoveCursor` → `sendDownUpKeyEvents(DPAD_LEFT/RIGHT)`); in English mode a swipe-up (>16 dp) on any letter key commits the **uppercase** letter (`attachLetterSwipeUp`); backspace repeats after 400 ms at 80 ms via `Handler`. Gesture specs come from the IR (`gestures:`, `repeat:`).
- Digits in Chinese mode: with an **empty** buffer a digit is committed as plain text (it used to be fed to the engine, produce no candidate and get wiped by the dead-code rule, so `1`–`0` typed nothing); with a composition alive the digit keeps its "select candidate" meaning and an unmatched one is swallowed. English mode commits letters/digits directly, so the rule only applies to Chinese.
- Mode switch actions: entering English clears the code area (`engine.reset()` + empty candidates) and shows the English page; returning to Chinese re-queries candidates if a buffer survived (`requeryCandidatesIfChinese()`).
- Hide button `▼` (`btn_hide_keyboard` / role `hide`): **tap** = `requestHideSelf(0)` (hide IME); **long-press** = toggle `hide_virtual_keyboard` preference (full keyboard ↔ 48 dp candidate bar only). `isHapticFeedbackEnabled = false` suppresses default long-press vibration.
- **Hiding the keyboard drops the composition** (`clearCompositionBeforeHide()`): `setComposingText("") + finishComposingText()` on the field, then `engine.reset()` + empty candidates. Nothing is committed. Called from the ▼ tap, `onWindowHidden()` (▼, Back, app/IME switch — the catch-all) and `onFinishInputView()`. Before that, hiding mid-composition left the inline composing text (`aad`, `情形`) behind in the field, and the next field inherited that stale composition. It is idempotent, and `onStartInputView(restarting=true)` never reaches it (an app `restartInput` keeps the buffer).
- Hardware D-pad: `KEYCODE_DPAD_LEFT`/`DPAD_RIGHT` move candidate selection by 1; `KEYCODE_DPAD_UP`/`DPAD_DOWN` call `KeyboardView.stepCandidatePage()` (`StepScrollView.stepPage()`), which pages the candidate row in a loop and highlights the first chip of the new page (`alignToSelection = false`).
- On-screen arrows / clipboard keys (English row 5): the `dpad` action calls `listener.onDpad()` → `sendDownUpKeyEvents(KEYCODE_DPAD_*)`; the `clipboard` action (`^A` / `^C` / `^V`) calls `currentInputConnection.performContextMenuAction(android.R.id.selectAll/copy/paste)`.
- Full hardware-key map (`MrubyimeIME.onKeyDown`): `Alt+Space` / `Shift+Space` toggles Chinese/English (bare `SHIFT` no longer toggles); `DPAD_LEFT/RIGHT` move the candidate selection; `DPAD_UP/DOWN` page it; `DEL`, `SPACE`, `ENTER` are routed to the composition handlers while a buffer/candidate exists; `ESCAPE` clears the composition (`engine.reset()`); any printable `a–z A–Z 0–9 , . ' [ ]` goes through `onKeyPressed`. **A held key's repeats run the same code as the first press** — the only `!repeating` guard is the Alt/Shift+Space hotkey. They used to fall through to `super.onKeyDown`, so the *app* inserted the raw character: holding `a` typed `aaaa` straight into the text while the engine buffer only ever got one `a`, and backspacing cleared the buffer but left those letters behind (the Titan 2's built-in QWERTY makes this easy to hit). A repeated `DEL` still falls through when the buffer is empty, so the app deletes its own text.
- Storage mirrors `KeyboardLayoutFiles`… (see the `.cin` section): the table file pairs are `dicts/active.cin` (user import) and `dicts/mrubyime.cin` (editable copy of the built-in). `sync()` reconciles both, newer wins (1 s tolerance), in **both** directions, so a root/Shizuku edit also reaches the Android/data mirror.
- Settings: `MrubyimeSettingsActivity` is a scrollable control panel. **It no longer sizes the keyboard or sets fonts**: 候選列高度／按鍵區高度／左右下預留／編碼區寬度／候選字字體／按鍵字體 are all owned by the layout DSL (`height bar:`/`height body:`, `padding left:/right:/bottom:`, `buffer weight:`/`candidates weight:`, `buffer font:`, `candidates font:`, per-key `font:`). The old `card_size`/`card_font` section blocks newly wrote those prefs and overrode the IR; they are gone including "恢復預設高度與字體設定", and the stale pref keys (`candidate_bar_height`, `keyboard_body_height`, `keyboard_bottom_padding`, `keyboard_left_padding`, `keyboard_right_padding`, `candidate_font_size`, `key_font_size`, `buffer_width_weight`, `buffer_width_follow_layout`) are simply ignored — `applyKeyboardSize()` calls `KeyboardView.layoutHeightPx()`/`applyLayoutMetrics()` which read the IR. To restore default sizes use 「恢復內建佈局」.
  - Remaining preferences are behaviour switches only: `hide_virtual_keyboard`, `light_theme`, `auto_commit`, `clear_dead_code`, `max_code_clear`, `inline_composing_mode`, plus the DSL section (`layouts/keyboard.rb`).
  - Section order is 系統設定 → **即時打字測試** → 外觀與模式 → 輸入框內聯顯示 → 輸入法碼表（.cin） → 鍵盤佈局（ruby dsl）. The engine (mruby) card was removed with user engines; the `card_test` block sits **above `card_display`** and carries **only the test `EditText`** — `acc_test` and `sec_test_title` were removed, so the field has no title bar of its own.
  - The `ctx` handed to the DSL no longer carries `bar_height`/`body_height`/`left_pad`/`right_pad` (they came from the removed prefs).
  - **Button layout is one column of equal-width plates, one single style**: `applyTheme()` paints **all 15 buttons** the same way — Light Mode: white plate + 1 dp black frame + black ink; Dark Mode: clear plate + 1 dp white frame + white ink — with an 8 dp corner radius (the test field stays square), `gravity = START or CENTER_VERTICAL` and 16 dp side padding, so every label sits on the left edge. There is deliberately **no filled CTA variant** any more (the old black-fill/white-ink group is gone). `normalizeButtonWidths()` (called once from `onCreate`, after `applyTheme()`) then measures each label with the button's own `paint` and writes `layoutParams.width` = widest label + its left/right padding (min 112 dp, capped at screen width − 96 dp), so every button shares one width and one centre line; measuring (not a hard-coded dp) keeps it right under a non-default `font_scale`. Every button is a **direct child of its card's vertical `LinearLayout`** (the old two-per-row horizontal wrappers are gone), centred with `layout_gravity="center_horizontal"` and separated by `marginBottom=8dp`. **The page has no decoration bars at all**: the 4 dp brand bar and the seven 5 dp section accents (`brand_bar`, `acc_*`) were deleted, so a section is just its title plus spacing. That is why the two 「用外部編輯器開啟」 buttons drop the file name (it is the status line right above) — the longer label would have pushed every button in the page wider.
- Keyboard height & padding: total height is `IR height.bar + IR height.body + IR padding.bottom` (or `bar + padding.bottom` when key rows are hidden), clamped to `screenHeightPx()` and enforced in `KeyboardView.onMeasure` via `EXACTLY`. Left/right/bottom padding comes from `IR padding` through `KeyboardView.setPadding(leftPaddingPx, 0, rightPaddingPx, bottomPaddingPx)`.
- **Theme**:
  - **Light Mode (default, `light_theme=true`)** and **Dark Mode (`false`)**. Both themes are declared as token maps (`theme :dark` / `theme :light` in `keyboard_layout.rb`) and resolved by `KeyboardLayoutRepository.ThemeResolver`; `KeyboardView.applyTheme()` only applies the resolved colours to the generated views/chips.
  - **Dark Mode**: `bar`/`key` `#3A3A3C`, `keyPressed` `#505054`, `seam` `#1C1C1E`, `keyBorder` `#1C1C1E` (the same deep tone as `seam`, so the per-side seam path draws a visible 1 dp grid between the `#3A3A3C` keys), ink `#FFFFFF`; the selected chip (and the Chinese placeholder) gets a **2 dp white bottom rule** and the unselected chips a visible dotted `seam` frame. Because `keyBorder` is set, the **keyboard keys are plain plates (no press selector)** in Dark Mode — the key/keyPressed selector is no longer used by the built-in keys (`keyPressed` survives only for the `flat` punctuation/hide keys on the candidate bar).
  - **Light Mode (e-ink)**: `bar` white `#FFFFFF`, `key` white with `keyBorder` `#000000` (1 dp **per-side seam**, no press state), `seam` white, ink black; the selected chip / Chinese placeholder has a **2 dp black bottom rule** and the Chinese bar has a **1 dp black top rule** (`bar border: { …, side: :top }`); the dotted `seam` chip frame is white-on-white so it disappears. Both themes paint the 1 dp `keyBorder` grid via `KeyboardView.gridKeyDrawable()`.
  - **Colour tokens** (all optional, resolved left-to-right by `KeyboardView.themed()`, so a layout can define only what it changes): `bar`/`barInk` (candidate bar + its symbol keys), `buffer`/`bufferInk`, `chip`/`chipInk` (unselected candidate), `chipSelected`/`chipSelectedInk`/`chipMark` (selected candidate plate/ink/underline), `key`/`keyInk`/`keyPressed`/`keyBorder`, `seam` (root behind the keys), `muted` (`sub_label`). Per-key overrides: `ink:`/`bg:` and `style: { border: { color:, width: }, radius: }`.
  - **No IME animation**: `MrubyimeIME.applyNavigationBarTheme()` also sets `window.attributes.windowAnimations = R.style.NoIMEAnimation` (enter/exit `@null`), so the panel appears and disappears without the system slide.
  - Navigation bar: `MrubyimeIME.applyNavigationBarTheme()` sets `window.navigationBarColor` (`#000000` / `#FFFFFF`) and toggles `SYSTEM_UI_FLAG_LIGHT_NAVIGATION_BAR`. Called on theme change and in `onStartInputView()`.
